# Campaign 001 — Six RTX 4090s vs A100

**Status: planned. No GPU measurements have been collected in this repository.**

## What we know
- RTX 4090 inventory: 6 cards, physical placement unverified.
- A100 available; device count, 40/80GB SKU, PCIe/SXM form factor, MIG and topology unverified.

## Questions in order
### Gate 0: Discover before benchmarking
Read-only inventory:
```bash
hostname
nvidia-smi -L
nvidia-smi topo -m
nvidia-smi --query-gpu=index,name,uuid,memory.total,driver_version,pci.bus_id,power.limit --format=csv
```
Save sanitized output and record OS, CPU, NUMA topology, GPU processes and permission from machine operator. Check whether each device is busy.

### Experiment 1: Single-card memory roofline
- Predict effective memcpy bandwidth and bandwidth-limited behavior with increasing tensor size.
- Vary bytes moved, access patterns and transfer path; separate H2D/D2H from device-to-device transfers.
- Compare observed bytes/s to the **correct SKU's** theoretical bandwidth with caveats.
- Do not infer L1/L2 directly from a single memcpy test.

### Experiment 2: Compute roofline
- Benchmark FP32, FP16/BF16 or TF32 when supported in the exact same numerical/quality contract.
- Sweep matrix shape, batch and implementation; compare vendor libraries to custom kernels.
- Capture achieved TFLOP/s, profiler metrics, and numerical error.

### Experiment 3: Single-card LLM latency
- Choose one model and fixed requests; confirm model fits each single card.
- Report prefill throughput, decode throughput, TTFT, p50/p95 latency, concurrency and memory use.
- Keep runtime, quantization and model revision explicit; acknowledge when GPU-specific kernels differ.

### Experiment 4: Communication and multi-card scaling
- Verify which 4090s are on the same host before selecting a group.
- Measure P2P capability and NCCL communication, with topology capture.
- Compare **data parallel** throughput independently from **model parallel** latency.
- Test 1/2/4/6 only if topology and scheduling permit; do not assume six can form one local NCCL group.
- Test A100 multi-card communication only if multiple A100 cards and links actually exist.

### Experiment 5: Optimize one real bottleneck
- Profile a reproducible workload and publish one intervention.
- Compare correctness and end-to-end results with matched configurations.
- Record cases where the optimization loses.

## Definition of a publishable result
The same commit includes executable source, invocation commands, hardware inventory, raw CSV/JSON, statistical summary, correctness checks, and a concise explanation that links the observed bottleneck to an architecture principle.

## First checkpoint
Only Gate 0 is appropriate without an approved hardware testing window. Do not publish performance charts before measurements.
